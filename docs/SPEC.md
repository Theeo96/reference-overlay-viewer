# 레퍼런스 이미지 뷰어 기능 및 동작 명세

작성일: 2026-11-19 KST
상태: 사용자 요구사항을 정리한 구현 기준. 2026-11-19 전체 구현을 진행했으며 아래 기본값을 채택했다. 실제 검증 범위와 조정 사항은 VERIFICATION.md에 기록한다.

## 1 목적과 범위

그림, 디자인, 모델링 등 PC 작업 중 참고 이미지를 작업창 위에 겹쳐 표시한다. 이미지가 보이는 영역을 클릭해도 아래 작업창을 그대로 조작할 수 있어야 한다. 뷰어의 상단 바만 예외로 항상 직접 조작할 수 있다.

첫 버전은 Windows 10/11, 정지 이미지 한 장을 표시하는 뷰어 창 한 개를 대상으로 한다. 여러 이미지 동시 표시, 갤러리, 탭, GIF 재생, 이미지 파일 자체의 수정·저장, 웹 서비스와 클라우드 동기화는 후속 범위다. 편집 모드는 뷰어 표시 상태를 조절하는 모드이며 원본 이미지 편집기가 아니다.

## 2 화면 구성

```text
┌───────────────────────────────────────────────────────┐
│ 열기  편집 모드 ON/OFF  불투명도  맞춤  배율  …  —  × │ ← 항상 불투명
├───────────────────────────────────────────────────────┤
│                                                       │
│                  참고 이미지                          │ ← 불투명도 조절
│                                                       │
└───────────────────────────────────────────────────────┘
```

상단 바와 본문은 사용자에게 하나의 창처럼 보이고 함께 이동·최소화·복원·종료한다. 상단 바 빈 부분을 충분히 확보해 드래그 이동에 사용한다. 버튼과 슬라이더를 누를 때 창 이동이 발생하지 않는다. 좁은 폭에서는 추가 기능을 메뉴로 모으고 편집 토글과 닫기 등 핵심 제어를 유지한다.

상단 바는 불투명도 설정에 영향을 받지 않는다. 본문은 이미지, 배경 및 본문에 추가되는 보조 표시까지 같은 불투명도 정책을 적용한다. 조작 버튼은 상단 바에 배치한다. 투명도는 **불투명도 0~100%**로 표시해 100%가 완전히 보이는 상태임을 명확히 한다. 0%에서도 상단 바는 보여야 한다.

## 3 편집 모드 계약

토글 표시 이름은 **편집 모드**로 하고 ON/OFF 상태를 글자로도 보여준다. 첫 실행 기본은 OFF로 제안한다. 재실행 시 이전 모드와 관계없이 OFF로 시작해 다른 작업을 우연히 가로채지 않게 한다.

| 동작 | 편집 모드 OFF | 편집 모드 ON |
| --- | --- | --- |
| 이미지 표시 | 항상 위, 지정 불투명도 | 항상 위, 지정 불투명도 |
| 본문 클릭 | 뒤 작업창에 전달, 뷰어 활성화 안 함 | 뷰어 입력으로 처리, 필요 시 활성화 |
| 본문 드래그 | 뒤 작업창 드래그 | 이미지 내부 이동 |
| 본문 마우스 휠 | 뒤 작업창에 전달 | 포인터 위치 기준 확대·축소 |
| 창 테두리 크기 변경 | 비활성, 입력을 가로채지 않음 | 가장자리·모서리에서 가능 |
| 상단 바 빈 영역 드래그 | 뷰어 전체 이동 | 뷰어 전체 이동 |
| 상단 바 클릭 및 버튼 | 활성화 및 조작 가능 | 활성화 및 조작 가능 |
| 열기·불투명도·편집 토글·숨기기·닫기 | 조작 가능 | 조작 가능 |
| 배율·맞춤·크기 변경 제어 | 비활성 표시 | 조작 가능 |

OFF 상태에서 본문 클릭을 감지해 이미지를 선택하거나 포커스를 되돌리는 방식은 사용하지 않는다. 운영체제가 실제 아래 창으로 입력을 전달하도록 한다. 단순히 클릭해도 아무 변화가 없는 것과 클릭 통과는 서로 다르다.

ON→OFF 전환은 배율, 이미지 위치, 창 위치 및 크기를 보존한다. 드래그 도중 전환되면 마우스 캡처와 리사이즈 상태를 해제하고 남은 입력이 뷰어에 붙잡히지 않게 한다. OFF→ON 전환도 이미지가 튀거나 배율이 초기화되지 않아야 한다.

상단 바를 클릭하면 제어권이 뷰어로 옮겨가는 것은 요구된 정상 동작이다. 이후 본문을 통해 뒤 작업창을 클릭하면 그 작업창이 정상적으로 활성화되어야 한다. OFF 상태의 본문 호버, 표시 갱신, 창 이동 완료 및 모드 전환 과정이 임의로 뒤 창의 포커스를 빼앗지 않도록 검증한다.

## 4 이미지 크기와 맞춤

모든 맞춤은 **상단 바를 제외한 본문 크기**를 기준으로 하며 원본 종횡비를 유지한다. 기본 정책은 이미지를 창에 맞추는 것이고, 이미지 파일을 열 때 화면을 벗어나도록 창 자체를 확장하지 않는다.

| 명령 | 동작 |
| --- | --- |
| 전체 맞춤 | 이미지 전체가 본문 안에 들어오는 배율. 남는 공간은 여백 |
| 가로 맞춤 | 이미지 가로가 본문 가로와 일치. 세로가 넘치면 이미지 이동으로 탐색 |
| 세로 맞춤 | 이미지 세로가 본문 세로와 일치. 가로가 넘치면 이미지 이동으로 탐색 |
| 실제 크기 100% | 원본 픽셀 기준 표시. 고해상도 배율 환경의 정의는 아래 기준 적용 |
| 수동 확대·축소 | 휠, 상단 +/- 버튼 또는 배율 입력으로 조절 |

초기 이미지 열기는 전체 맞춤과 중앙 정렬로 시작한다. 맞춤 모드에서는 창 크기가 바뀔 때 같은 정책으로 배율을 재계산한다. 수동 모드에서는 창 크기를 바꿔도 배율을 유지하고, 가능한 한 화면 중심에 보이던 이미지 지점을 유지한다. 휠이나 수동 배율 조절을 하면 수동 모드로 전환한다.

초기 제안 범위는 5~1600%이며 큰 이미지 등에서 적절한지 구현 중 확인한다. 범위를 벗어난 값, 0, 음수, 숫자가 아닌 값은 안전하게 거부하거나 제한하며 현재 배율을 망가뜨리지 않는다. 휠 확대는 포인터 아래 이미지 지점을 기준으로 하고 상단 버튼은 본문 중심을 기준으로 한다.

WPF는 DIP 단위를 사용하므로 100%의 의미를 명확히 구현한다. **실제 크기 100%는 이미지 원본 1픽셀을 현재 모니터의 화면 1픽셀에 대응시키는 것**으로 정의한다. DPI 변환을 적용하고 배율이 다른 모니터로 옮겼을 때도 다시 계산한다. 파일의 DPI 메타데이터만으로 크기가 달라지지 않도록 한다.

이미지 이동은 ON 상태의 본문 왼쪽 버튼 드래그로 제공한다. 이미지가 뷰 밖으로 완전히 사라지지 않게 제한한다. 전체 맞춤 또는 중앙 정렬 명령으로 복구할 수 있어야 한다. 첫 버전에서 본문 스크롤바는 생략하고 드래그 이동을 사용한다.

## 5 창 제어와 표시

- 일반 Windows 작업창 위에 계속 표시한다. 상단 바와 본문은 같은 그룹으로 겹침 순서를 유지한다.
- 창 이동은 모드와 무관하게 상단 바의 빈 부분을 드래그한다.
- ON에서는 테두리·모서리 리사이즈를 제공한다. 최소 크기는 상단 바 핵심 제어가 사용 가능한 수준으로 제한한다.
- OFF에서는 리사이즈용 보이지 않는 창이나 테두리가 뒤 작업을 방해하지 않게 한다.
- 상단 바의 — 버튼으로 그룹을 최소화하고 작업표시줄에서 함께 복원한다. 별도 빠른 숨기기/다시 표시는 전역 단축키를 제공하며 키 충돌 시 대체 설정이나 명확한 안내를 준다. 단축키 값은 첫 구현 시 충돌을 확인해 확정한다.
- 닫기를 누르면 본문, 보조창, 전역 단축키와 프로세스를 함께 정리한다.
- 다중 모니터의 음수 좌표, 서로 다른 배율, 모니터 분리 후 복원을 처리한다. 저장된 위치가 화면 밖이면 사용 가능한 화면 안으로 복구한다.
- 독점 전체화면, 보안 데스크톱 및 다른 프로그램의 항상 위 창보다 무조건 우선하는 것은 보장하지 않는다. 일반 창과 테두리 없는 창을 우선 검증한다.

## 6 파일과 설정

첫 버전 필수 포맷은 PNG, JPEG, BMP다. PNG 알파 채널을 보존하고 사진의 EXIF 회전을 반영한다. WebP, TIFF, GIF 등은 디코더와 구현 비용을 확인한 뒤 별도 추가한다. 상단 바의 열기 버튼을 기본 진입점으로 하고, ON 상태의 파일 드롭은 여력이 있을 때 추가한다. OFF 본문은 파일 드롭도 가로채지 않는다.

손상되거나 미지원인 파일을 열면 기존 이미지를 유지하고 오류를 표시한다. 큰 이미지는 UI 정지와 과도한 메모리 사용을 피하도록 로딩 경로와 크기 제한을 검토한다. 원본 파일을 수정하지 않고 파일을 계속 잠가두지 않는다. 이미지가 없을 때에도 OFF 본문은 클릭을 통과시킨다.

창 위치·크기, 불투명도, 맞춤 방식, 마지막 이미지 경로를 사용자별 로컬 설정에 저장한다. 마지막 이미지는 경로가 유효할 때만 복원하고 없으면 빈 상태로 시작한다. 로컬 설정은 저장소 밖의 앱 데이터 폴더에 저장한다. 깨진 설정은 기본값으로 복구한다. 편집 모드는 OFF로 시작한다.

## 7 구현 방향과 검증할 위험

C# + WPF + Win32 API를 사용한다. 상단 제어창은 일반 입력을 받고, 별도 이미지 창에 반투명 표시와 모드별 입력 통과를 적용하는 구조를 우선 시도한다. 이동·크기·DPI·표시 상태를 공통 상태에서 동기화한다. 하나의 작업표시줄 항목과 자연스러운 포커스 전환을 유지한다.

본문은 layered window와 WS_EX_TRANSPARENT 조합의 입력 통과, WS_EX_NOACTIVATE 등의 활성화 정책을 검토한다. ON 전환 때 필요한 스타일을 복원한다. WPF 창의 Opacity만 낮추거나 IsHitTestVisible을 끄는 것으로 다른 앱에 입력이 전달된다고 가정하지 않는다. HTTRANSPARENT만 사용하는 방식도 프로세스 간 입력 통과의 입증으로 삼지 않는다.

설계 가설은 1단계에서 실제 다른 앱으로 검증한다. WPF와 네이티브 스타일 충돌, owned window 활성화, 본문 위로 상단 바가 잘못 겹치는 문제, 리사이즈 잔여 영역, DPI 이음새 등이 확인되면 창 구성이나 렌더링 경로를 조정하고 근거를 기록한다.

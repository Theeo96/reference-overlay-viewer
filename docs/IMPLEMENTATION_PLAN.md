## 1 실행 환경과 핵심 창 동작 검증

첫 작업은 보기 좋은 UI보다 입력 통과와 편집 토글을 실제로 입증하는 데 집중한다.

작업:

1. 프로젝트 및 상위 경로 지침을 읽고 현재 파일 상태를 확인한다. `dotnet --info`, 설치된 Windows SDK, Git과 GitHub 인증 계정을 확인한다. 인증 정보 원문을 출력하지 않는다.
2. 설치 환경 및 당시 공식 지원 상태를 확인해 .NET LTS와 Windows 타깃을 확정한다. 필요 시 적절한 SDK를 준비한다.
3. WPF 솔루션을 생성한다. 앱 소스는 `src/ReferenceOverlayViewer`, 필요한 순수 로직 테스트는 `tests`로 구성한다. 구현 전 사용한 도구와 빌드 방법을 README에 기록한다.
4. 불투명 상단 바와 반투명 본문을 띄우는 최소 프로토타입을 만든다. 개발용 자작 이미지로 입력 동작을 확인한다.
5. 편집 모드 토글, 본문 입력 통과, 비활성화 상태의 포커스 정책, 항상 위 표시, 상단 바 이동과 활성화를 구현한다.
6. 두 창이 함께 이동·최소화·복원·종료하고 하나의 작업표시줄 항목으로 보이게 한다. ON에서 리사이즈, OFF에서 테두리 입력 통과를 구현한다.
7. 메모장 또는 브라우저 등 별도 프로세스에서 실제 클릭·드래그·휠·타이핑을 검사한다. 프로토타입이 실패하면 창 구조를 조정한 뒤 재검증한다.
8. .gitignore와 .gitattributes를 준비하고 로컬 Git 저장소 및 main 브랜치를 초기화한다. 빌드 확인과 비밀정보·개인 이미지 제외 확인 후 초기 커밋을 만든다.
9. 사용자가 요청한 연동 GitHub 계정에 public 저장소를 만들고 main을 푸시한다. 저장소 URL, 공개 상태, 로컬·원격 커밋 일치를 확인한다.
10. 실제 구현 범위와 미검증 항목을 STATUS.md에 기록한다.

완료 기준:

- 앱 실행과 종료가 가능하고 편집 모드 ON/OFF의 핵심 동작이 실제 다른 앱에서 확인된다.
- 50% 불투명도에서도 OFF 본문을 통한 클릭과 드래그가 뒤 창에 전달된다.
- OFF 상단 바를 눌러 활성화하고 드래그해 이동할 수 있다.
- 빌드 결과와 수동 검증 결과를 구별해 기록한다.
- 초기 커밋과 공개 원격 푸시가 완료되거나, 인증·도구 문제 등 실제 장애가 정확히 기록된다. GitHub 장애로 독립적인 로컬 구현까지 중단하지 않는다.

## 2 이미지 열기와 기본 표시

작업:

- PNG/JPEG/BMP 로딩, 종횡비 유지, PNG 알파, EXIF 회전을 구현한다.
- 열기 취소, 손상 파일, 미지원 파일, 파일 삭제를 처리한다. 교체 실패 시 기존 이미지를 유지한다.
- 파일을 잠그지 않는 로딩, 큰 이미지에서 UI 응답성과 메모리를 확인한다.
- 불투명도 슬라이더를 연결하고 본문 0%, 50%, 100%에서도 상단 바가 불투명한지 확인한다.

완료 기준: 정상 이미지 열기와 교체가 가능하고 오류로 앱이 종료되지 않는다. 원본 파일은 수정하지 않는다.

## 3 편집 조작과 이미지 맞춤

작업:

- 전체 맞춤, 가로 맞춤, 세로 맞춤, 실제 크기 100%, 수동 배율을 구현한다.
- 본문 휠 확대·축소, 이미지 드래그 이동, 상단 +/-와 배율 입력, 중앙 정렬을 구현한다.
- OFF에서는 이미지 편집 제어를 비활성화하고 표시 상태를 유지한다. 열기·불투명도·상단 바 이동은 사용할 수 있다.
- 맞춤 모드와 수동 모드의 리사이즈 정책을 분리한다. 모드 전환 시 이미지 점프를 방지한다.
- 드래그 도중 OFF 전환 시 캡처 해제와 상태 정리를 구현한다.

완료 기준: SPEC.md의 모드 표와 맞춤 수식에 따라 동작하고, 가로/세로 맞춤으로 넘치는 부분을 ON에서 탐색할 수 있다.

## 4 실사용 안정성과 상태 복원

작업:

- 창 위치·크기·불투명도·맞춤 방식·마지막 이미지 경로를 사용자 앱 데이터 폴더에 저장한다.
- 첫 시작 및 재시작은 편집 모드 OFF로 한다.
- 빠른 숨기기/표시 전역 단축키와 충돌 처리를 구현한다. 숨긴 상태에서 포커스를 빼앗지 않고 다시 표시되는지 확인한다.
- 다중 모니터, DPI 변경, 화면 밖 위치 복구, 최소 크기, 상단 바 좁은 폭을 처리한다.
- 보기 영역과 제어창의 틈·겹침·프레임 잔상, 최소화 후 남는 창, 종료 후 남는 프로세스를 검사한다.

완료 기준: 정상 재실행과 모니터 구성 변경 시 상단 바를 잃지 않는다. 저장된 설정이 깨져도 실행 가능하다.

## 5 배포와 최종 확인

작업:

- Release 빌드와 Windows x64 자체 포함 배포를 준비한다. 단일 exe 배포는 네이티브 구성·시작 비용을 확인한 후 선택하며, 필요한 경우 exe와 관련 파일이 든 폴더를 배포한다.
- 개발 SDK 없이 실행 가능한 패키지를 확인한다. ARM64 지원은 별도 검증 후 추가한다.
- README에 실행, 편집 모드, 이미지 맞춤, 단축키, 설정 위치, 알려진 제한을 기록한다.
- 라이선스는 사용자가 별도로 선택하지 않았다면 임의의 오픈소스 라이선스를 부여하지 않는다. GitHub 공개와 오픈소스 라이선스 부여는 별개로 처리한다.
- ACCEPTANCE_TESTS.md 결과를 기록하고 알려진 미검증 환경을 남긴다.
- 기능별로 적절한 커밋을 만들고 승인된 공개 저장소에 푸시한다. GitHub Release 배포는 별도 요청 또는 명확한 배포 범위에 따라 수행한다.

완료 기준: 사용자가 앱을 실행해 이미지를 열고 ON에서 조절한 뒤 OFF로 전환하여 뒤 작업창을 사용할 수 있다. README와 실제 배포물의 동작이 일치한다.

## 기술 구성 초안

| 구성 | 책임 |
| --- | --- |
| 상단 제어창 | 불투명 UI, 창 이동, 모드 토글과 각 명령 |
| 이미지 표시창 | 이미지 렌더링, 불투명도, ON 상태의 이미지 조작 |
| 창 동기화 담당 | 두 창의 위치·크기·DPI·겹침 순서·최소화·종료 |
| Win32 연동 | layered/transparent/noactivate 스타일, 활성화 정책, 전역 단축키 |
| 표시 상태 | 모드, 배율 정책, 확대율, 이동량, 파일 및 불투명도 |
| 이미지 로딩 | 디코딩, 회전, 오류 및 파일 잠금 방지 |
| 설정 저장 | 버전이 있는 사용자별 로컬 설정과 기본값 복구 |

과도한 계층을 먼저 만들지 않는다. 상태와 맞춤 계산처럼 검증 가치가 있는 순수 로직은 UI에서 분리한다. 모드 및 창 상태의 진실을 한 곳에서 관리해 상단 바와 본문 상태 불일치를 막는다.

## 검증 전략

빌드·맞춤 계산 테스트·실제 OS 입력 검증을 나눠 수행한다. 자동 테스트는 종횡비별 맞춤 배율, DPI 변환, 상태 전환, 설정 오류 복구처럼 회귀 위험이 있는 로직에 집중한다. 클릭 통과와 포커스는 단위 테스트만으로 통과 판정하지 않는다. 검증에 GUI 접근이 없으면 그 항목을 미검증으로 남기고 사용자가 실행할 수 있는 구체적인 절차를 제공한다.

## 공개 저장소 운영

첫 구현 시작 시 커밋과 public push를 수행한다는 사용자 지시를 적용한다. 연동 계정은 당시 인증된 계정을 확인해 사용하고 추측하지 않는다. 원격 저장소 이름이 이미 있으면 내용을 검사해 덮어쓰지 않는 경로를 선택한다. force push나 기존 저장소 삭제는 이 계획에 포함하지 않는다.

커밋 전 제외 대상: bin/obj, .vs, 배포 산출물, 로컬 설정, 개인 이미지, 로그, 인증 정보. 초기 커밋에는 문서와 빌드 가능한 구현을 포함한다. README의 상태를 갱신하고, 푸시 후 실제 공개 여부와 원격 커밋을 확인한다.
